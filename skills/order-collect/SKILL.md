# order-collect

설정된 모든 판매 채널의 주문을 한번에 조회하고 통합 요약하는 워크플로우.

## When to use

- "오늘 주문 몇 개야?", "주문 모아줘", "전채널 주문 현황" 요청 시
- "최근 1개월 주문데이터 CSV로 뽑아줘", "지난달 주문 엑셀로 줘" 요청 시
- 매일 아침 주문 현황 파악할 때
- 멀티채널 주문을 한눈에 보고 싶을 때
- 정산/분석을 위해 주문 데이터를 처음 수집할 때

## Prerequisites

- 최소 1개 판매 채널 설정 완료
- `sppt status`로 채널 연결 확인

## Steps

### 0. 파일 내보내기 요청

사용자가 주문 파일을 요청하면 채널별 목록을 따로 출력하지 않고 아래 명령을 바로 실행합니다.

```bash
sppt order export all --period 30d --format csv
```

- "최근 1개월"은 `--period 30d`, "지난달"은 `--period last-month`로 해석합니다.
- 엑셀 파일을 명시하면 `--format xlsx`를 사용합니다.
- 기본 파일에는 수령인·전화번호·주소가 없습니다. 출고 목적으로 개인정보가 필요한 경우에만 `--include-pii`를 추가합니다.
- W컨셉·무신사는 브라우저 수집을 새로 실행하지 않고 이미 저장된 주문을 파일에 포함합니다. 무신사 주문수집은 무신사와 무신사 글로벌을 같은 로그인·이메일 인증으로 함께 가져오며, 두 채널을 구분해 파일에 포함합니다. 완료 후 해당 채널의 마지막 성공 수집 시각을 함께 알립니다.
- 완료 후 파일 경로, 주문상품 행 수, 제외된 채널과 사유를 사용자에게 알립니다.

파일 요청이 아니면 아래 수집·요약 단계를 따릅니다.

### 1. 채널 상태 확인

```bash
sppt status
```

연결된 채널 목록을 파악합니다. 연결 실패한 채널이 있으면 사용자에게 알립니다.

### 2. 수집 범위 결정

최근 1일치 주문이 있는지 확인해 첫 수집인지 판단합니다:

```bash
sppt order list cafe24 --days 1
```

**결과가 0건이거나 오류인 경우 → 첫 수집 가능성 높음:**

사용자에게 확인합니다:

> 저장된 주문이 없습니다. 처음 수집이라면 더 긴 기간이 필요할 수 있어요.
> 몇 일치를 가져올까요? (예: 30일, 90일, 또는 직접 입력)

사용자가 기간을 답하면 그 값을 `--days N`으로 사용합니다.
답하지 않거나 "그냥 해줘"이면 **90일**을 기본으로 사용합니다.

**결과가 있는 경우 → 일일 체크:**
`--days 1`을 사용합니다.

### 3. 채널별 주문 조회

결정된 기간(`DAYS`)으로 연결된 각 채널에서 주문을 조회합니다:

```bash
sppt order list cafe24 --days DAYS
sppt order list coupang --days DAYS
sppt order list smartstore --days DAYS
sppt order list shopify --days DAYS
```

- W컨셉·무신사는 브라우저 수집 채널이라 `order list`로 직접 재수집하지 않습니다. 무신사 수집 1회에 국내 주문 내역과 글로벌 주문 내역을 함께 읽고, 저장된 `musinsa`·`musinsa-global` 주문은 `order export all`에 각각 포함됩니다.

사용자가 특정 기간을 명시적으로 요청했으면 그 기간을 우선합니다.

### 4. 통합 요약

채널별 결과를 통합하여 사용자에게 보여줍니다:

```
📦 주문 현황 (최근 N일)
─────────────────────────────────────
채널          신규    처리중    완료    합계
cafe24         3       2        5      10
coupang        5       1        8      14
smartstore     2       0        3       5
shopify        1       0        1       2
─────────────────────────────────────
합계          11       3       17      31
```

첫 수집으로 많은 데이터를 가져온 경우: "N일치 주문 XXX건을 수집했습니다. 대시보드에서 정산 현황을 확인하세요." 안내를 추가합니다.

### 5. 미처리 주문 안내

신규(미확인) 주문이 있으면 즉시 처리가 필요함을 안내합니다:

- 미확인 주문 → `/sppt-order-fulfill`로 처리 안내
- 발주 확인 후 송장 미등록 → 송장 등록 필요 안내

### 6. 주문 상세 (선택)

사용자가 특정 주문을 더 보고 싶으면:

```bash
sppt order get <channel> <orderId>
```

## Error handling

- **채널 연결 실패**: 해당 채널 건너뛰고 나머지 채널 결과 표시, 재인증 안내
- **SmartStore 24시간 제한**: CLI가 자동으로 일 단위 순회하므로 걱정 불필요
- **Rate limit**: CLI rate limiter가 자동 처리
- **긴 기간 조회 시 속도 저하**: "N일치 조회 중입니다, 잠시 기다려 주세요." 안내 후 진행

## Notes

- 매일 아침 체크 루틴으로 활용하면 효과적
- Coupang은 발주 확인 전에만 취소가 가능하므로 빠른 확인 중요
- `--json` 플래그로 JSON 출력 가능 (자동화/파이프라인 연동 시)
- 첫 수집 후 대시보드 정산 페이지를 새로고침하면 데이터가 반영됩니다
